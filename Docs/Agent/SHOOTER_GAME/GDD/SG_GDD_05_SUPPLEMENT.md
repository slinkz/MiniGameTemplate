> **通知条队列规则**（v1.8 UI PK 新增）：
>
> | 属性 | 值 |
> |------|-----|
> | 最大队列长度 | **2**（当前显示 1 + 待显示 1） |
> | 超出处理 | 新通知**立即替换**当前显示的（当前通知快速淡出 0.1s → 新通知弹入） |
> | 同类型合并 | **不合并**（V2 道具种类少，合并逻辑开发成本不值得；直接替换更简洁） |
> | 每条显示时长 | 1.5s（不变） |
>
> **设计理由**：高掉率 + 磁吸被动激活时，2~3 秒内可能连续拾取 3~4 个道具。无限排队会导致通知堆积 6s+，过期信息仍在显示变成噪声。队列长度限 2 + 立即替换 = 通知永远及时。

> - 飞机区域唯一可能叠加的是"无敌帧闪烁 + DOT 粒子附着"——两者用不同表现层（Alpha 闪烁 vs 粒子特效）自然分离
> - 唯一需要抑制的情况：P0 受伤红闪期间，P5 通知条延迟 0.3s 弹出——避免正/负反馈信号同时到达

### 11.2 视觉区分——敌我子弹辨识

**核心原则**：玩家必须在 0.2 秒内分辨"这是我的子弹还是敌人的"。

| 属性 | 我方子弹 | 敌方子弹 |
|------|---------|---------|
| 颜色 | 蓝/青色系 | 红/橙色系 |
| 大小 | 较小（0.16 世界单位） | 较大（0.2 世界单位） |
| 形状 | 尖锐、流线 | 圆形、膨胀 |
| 拖尾 | 短拖尾 | 长拖尾 + 发光 |
| 运动方向 | 向上 | 向下 |

### 11.3 音效区分

| 行为 | 音效特征 |
|------|---------|
| 我方射击 | 清脆、短促、轻快（pew pew） |
| 敌方射击 | 低沉、有力、带警告感 |
| Buff 获取 | 上升音阶 + 叮咚 |
| DOT 触发 | 持续低频嗡鸣（燃烧=噼啪、中毒=咕嘟） |
| 道具拾取 | 明快的硬币/水晶声 |

### 11.4 性能预算

| 维度 | V1 预算 | V2 预算 | 理由 |
|------|---------|---------|------|
| 同屏 Entity | 40 | 60 | 新增敌弹 + 道具 Entity |
| 弹幕系统 bullet | 512 | 1024 | 敌我双方都发射 |
| DrawCall | ≤15 | ≤25 | 新增子弹类型 + VFX |
| Atlas 数 | 1 | 2 | 新增子弹/VFX atlas |

> **技能执行性能护栏**（v2.0 架构师 PK 新增）：
>
> V2 规模（6 技能 + 60 Entity）下，SkillComponent.Tick 中串行执行所有 ISkillEffect 的极端单帧耗时 ≈ 0.15ms（占 16.7ms 帧预算 < 1%），不需要分帧策略。
>
> **V3 触发条件**：当技能池扩展后，若单帧技能执行总耗时 > **1ms**，需引入"每帧最多执行 N 个技能"的分帧策略。

> **弹幕预算极端验证**（v2.0 架构师 PK 新增）：
>
> ```
> 极端场景：火力全开(SK-P04) + 疾风 Buff 同时激活
>   基础攻击：0.25s × 0.5 × 0.5 = 0.0625s → 32 发/s × 3s = 96
>   散射弹幕(SK-P01)：17/s × 3s = 51
>   追踪+激光+冲击波 ≈ 4
>   敌方弹丸 ≤ 30
>   总计 ≈ 181 << 1024 ✅
> ```
>
> 安全钳：AttackInterval 乘积不低于 0.05s（见 §5.4 Buff 叠加上限）。

> **失败面板"火力提示"逻辑**（v1.9 新增）：
> 1. 检查玩家是否有未解锁技能 → 若有，推荐**下一个按解锁条件最接近的技能**

#### 技能贡献统计口径（v1.9 UI PK 新增）

| 属性 | 值 |
|------|-----|
| 统计口径 | **总伤害占比**（每个伤害来源记录 damageSourceId → 结算时按 sourceId 汇总） |
| 分类 | 基础攻击 / 各主动技能(SK-P01~P06) / 被动反击(PA-04) / DOT |
| V2 实现 | 简单版——只在 DamageDealer.DealDamage 时累加 `Dictionary<string, int>` |
| V3 扩展 | 双维度（伤害 + 击杀），但 V2 只做伤害占比 |
| 展示方式 | 前 4 名按百分比横排，≤5% 的合并为"其他" |

> **damageSourceId 传递链**（v2.0 架构师 PK 新增）：
>
> ```
> SkillConfigSO.SkillId (如 "SK-P01")
>   → FireBulletsEffect.Execute() 时写入 Bullet.sourceTag
>   → BulletWorld NativeArray 增加 sourceTag 字段（int 类型，4 bytes/bullet）
>   → Bullet 碰撞时 → DamageContext.sourceId = bullet.sourceTag
>   → DamageDealer.DealDamage(context) → 累加 _damageStats[sourceId]
> ```
>
> - `sourceTag` 用 **int** 而非 string——NativeArray 不支持引用类型
> - 基础攻击 sourceTag = 0（默认值），技能从 1~6 编号
> - PA-04 反击弹幕使用专门的 sourceTag ID
> - DOT 的 sourceTag 直接取 DotConfigSO.DotId
> - V2 内存影响：1024 bullet × 4 bytes = **4KB**，可忽略

> **damageStats 数据生命周期**（v2.0 架构师 PK 新增）：
>
> | 阶段 | 操作 |
> |------|------|
> | 创建 | `BattleController.OnBattleStart()` 时创建，初始化所有 sourceTag 键值为 0 |
> | 冻结 | `BattleController.OnBattleEnd()` 时冻结——IsAllWavesCleared 且所有在飞弹丸消亡后触发 |
> | 传递 | OnBattleEnd 后将 `_damageStats` 的**快照副本**传递给结算面板 |
> | 销毁 | 结算面板持有自己的数据拷贝，不依赖 BattleController 存活。战斗 Scene 可安全卸载 |
> | 持久化 | V2 **不持久化**——纯局内临时数据。V3 按需扩展存档 |

#### 星级评价标准（v1.9 UI PK 新增）

| 星级 | 条件 | 玩家感受 |
|------|------|---------|
| ⭐ | 通关（基地 HP > 0） | "过了但险" |
| ⭐⭐ | 通关 + 基地 HP ≥ 50% | "打得不错" |
| ⭐⭐⭐ | 通关 + 基地 HP ≥ 80% | "碾压！" |

| 属性 | 值 |
|------|-----|
| 阈值标记 | **[占位符]**——50%/80% 待 playtest 调整 |
| 展示动效 | 星星依次弹出（0→1→2→3，每颗间隔 0.3s），三星时最后一颗放大弹跳 + 金色粒子爆发 |
| 历史最佳 | 选关界面显示每关历史最高星级 |
| 重玩钩 | 未满三星的关卡在选关界面显示"挑战三星！"标签 |
| 与付费的关系 | 三星难度 ≈ "当前火力刚好够碾压"——解锁/升级技能后更容易三星 → 间接付费激励 |

> **星级判定时机**（v2.0 架构师 PK 新增）：
>
> ```
> 最后一个敌机死亡
>   → EntitySpawner.IsAllWavesCleared = true
>   → 所有 Camp=Enemy 弹丸继续飞行（玩家仍需闪避）
>   → BulletWorld 中 Camp=Enemy 弹丸数 = 0
>   → BattleController.OnBattleEnd() 触发
>   → 冻结 damageStats + 读取 base.HealthComponent.CurrentHp
>   → 计算星级
>   → 传递给结算面板
> ```
>
> **选择"弹幕清场后"（方案 B）的理由**：
> - 最后几发弹的闪避/挡弹决策可能影响二星→三星——有意义的最终决策（P3 走位策略）
> - 延迟窗口：敌弹 Lifetime 3s，实际大多数弹 ≤1s 内命中或离屏，可接受
> - 避免"看到三星但被弹打成二星"的体验矛盾

### 11.8 数据权威原则（v2.1 工具 PK 新增）

> **铁律：禁止同一数据双源。**
>

> | 技能配置 | **ScriptableObject** | Unity Inspector | 6 个技能 SO，体量不需要 xlsx |
> | Buff 配置 | **ScriptableObject** | Unity Inspector | 7 个 Buff SO |
> | DOT 配置 | **ScriptableObject** | Unity Inspector | 3 个 DOT SO |
> | 道具/掉落配置 | **ScriptableObject** | Unity Inspector | ~8 个 Pickup + 2 个 DropTable |
> | 被动配置 | **ScriptableObject** | Unity Inspector | 4 个 Passive SO |
> | 关卡波次/敌机出场 | **Luban xlsx** | Excel 表格 | 大批量数据，Luban 优势区 |

> **后续迁移条件**：技能/Buff/道具等 SO 数量超过 **30** 个时，考虑 Luban 化，需编写"SO↔xlsx 双向同步工具"。
