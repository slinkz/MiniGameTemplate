# Design Pillars

> 定位：策划 Agent 做判断时的北极星。所有关卡、技能、UI、资产需求都应服务这些支柱。

| 支柱 | 玩家感受 | 设计要求 | 反例 |
|------|----------|----------|------|
| 零门槛上手 | 不看教程也能玩 | 玩家只控制移动；战斗和技能自动释放 | 手动瞄准、手动放技能 |
| 火力渐强 | 越打越满屏、越打越爽 | 技能、道具、Buff 带来可见火力变化 | 全局同一颗子弹 |
| 走位即策略 | 站位影响生存和输出 | 敌人/弹幕/掉落迫使移动选择 | 站哪都一样 |
| 可控紧张 | 死因清楚，有喘息 | 波次有松紧，危险态有明显反馈 | 屏幕淹没、看不懂怎么输 |
| 轻量配置 | 快速迭代 | 优先 SO/表格配置，工具可预览 | 新增普通内容必须改代码 |

## 当前硬约束

- ShooterGame 是竖版飞行射击，微信小游戏平台。
- V1/V2 主体验是自动攻击 + 虚拟摇杆移动。
- 基地扣血主要表达“敌机突破防线”，不要轻易改成复杂生命系统。
- UI 必须轻量，不遮挡战斗主体。
- 高频战斗表现必须考虑 WebGL/微信性能。

## 决策检查

设计方案提交前必须回答：

1. 它强化了哪一个支柱？
2. 它是否增加玩家操作负担？
3. 它是否能通过 SO 或低成本资产实现？
4. 玩家如何在 3 秒内感知到变化？
5. 失败或受挫反馈是否清楚？
