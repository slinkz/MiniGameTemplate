### UID-001 | 🔴 高 | 出战准备界面信息架构缺失交互规格

**涉及章节**：§3.1 出战准备界面设计
**质疑**：GDD 给出了出战准备界面的 ASCII 布局图，但**缺少关键交互规格**：

2. 被动技能"最多选 3 个"的选/取消操作如何交互？

**建议方向**：补充完整交互规格，至少包含：选择方式、状态反馈、操作流程、与选关界面的关系、按钮态定义。

### UID-003 | 🔴 高 | 战斗 HUD 信息密度急剧增加，缺遮挡安全分析

**涉及章节**：§11.1 战斗 UI 升级
**质疑**：V2 战斗 HUD 从 V1 的"暂停按钮 + 波次 + 基地血条"暴增到 **7 类 UI 元素**：
- 左上：被动技能栏（最多3个图标）
- 右上：Buff 图标栏（最多8个 Buff + 倒计时文字）
- 顶部全宽：Boss 血条（Boss 战时出现）
- 飞机下方：技能 CD 指示器
- 拾取位置：道具名称飘字
- 原有：暂停按钮 + 波次指示
- 原有：基地血条

**问题**：
1. Boss 血条占据画面顶部全宽时，与暂停按钮/波次指示/被动技能栏/Buff 栏 **四叠冲突**
2. 技能 CD 指示器在"飞机下方"——飞机是玩家控制移动的，CD 指示器会不会遮挡敌弹？
3. Buff 栏最多 8 个 Buff 的图标 + 倒计时全放右上角，在 750pt 宽的竖屏上放得下吗？
4. 被动栏 3 个 + Buff 栏 8 个 = 11 个图标+文字同时显示，信息过载

**潜在风险**：纵版射击游戏最宝贵的是**弹幕可见区域**。UI 元素从四个方向挤压可视区，玩家看不清敌弹就无法闪避——直接违反设计支柱 P4。

**建议方向**：
1. 做一张**像素级 HUD 布局稿**，标注每个元素的精确坐标和尺寸
2. Boss 血条出现时，被动栏/Buff 栏是否需要收起或重排
3. 技能 CD 指示器改为飞机周围环形而非独立 UI 元素
4. Buff 栏超过 4 个时的折叠/滚动方案

### UID-004 | 🟡 中 | 技能 CD 指示器"跟随飞机"的 FairyGUI 实现可行性

**涉及章节**：§11.1 技能 CD 指示器
**质疑**：GDD 说技能 CD 指示器在"飞机下方"。但玩家飞机是 Unity 世界坐标中的 Entity，而 FairyGUI 是独立坐标系。**FairyGUI 元素跟随世界坐标物体**需要每帧做坐标转换（世界→屏幕→FairyGUI），性能开销不可忽略。

现有 `SG_UI_DESIGN.md` 的飘字组件也有类似问题，但飘字是短暂出现后消失，CD 指示器却是**常驻**的。

**潜在风险**：在微信小游戏 WebGL 环境下，每帧坐标转换 + FairyGUI 组件 SetPosition 可能引起额外 drawcall 和 GC。

**建议方向**：考虑两个替代方案：
1. CD 指示器改为 HUD 固定位置（如左下角/右下角），不跟随飞机
2. CD 指示器用 Unity SpriteRenderer 实现而非 FairyGUI，直接挂在飞机 Entity View 上

### UID-011 | 🟡 中 | UID-003 追问：Boss 战 HUD 重排的被动栏位置不合理

**涉及章节**：Round 1 RE: UID-003
**质疑**：守方说 Boss 战时被动栏"移至 Boss 血条下方第二行"。但是：
