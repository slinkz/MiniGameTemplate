# 三、主动技能设计

### 3.1 玩家飞机主动技能

**设计目标**：玩家飞机拥有 **1 个基础攻击（自动）** + **最多 6 个技能槽（全部自动释放）**。**玩家在战斗中只需操控飞机移动，所有攻击和技能全自动触发。**

#### 基础攻击（始终存在，自动）

这是 V1 已有的 `AttackComponent`——持续自动射击，不占技能槽。

| 参数 | V2 更新值 | 说明 |
|------|----------|------|
| AttackInterval | 0.25s | 从 0.3s 微调，提升射速感 |
| BulletPattern | SG_PlayerBullet_Straight | 不变，单发直射 |
| AttackFireOffset | (0, 0.4) | 不变 |

#### 技能槽设计（v1.6 重大更新）

```
┌─────────────────────────────────────────────────┐
│                 玩家飞机                         │
│                                                 │
│  [基础攻击] ← AttackComponent（自动）            │
│  [技能槽 1~6] ← SkillComponent.SkillSlot[6]    │
│                                                 │
│  ※ 战前从已解锁技能中选择最多 6 个带入          │
│  ※ 所有技能 CD 好了就自动释放，玩家无需操作     │
│  ※ V2 已有 6 种技能，后期再扩充技能池           │
└─────────────────────────────────────────────────┘
```

**设计决策**（v1.6 更新）：单局最多带入 **6 个技能**，全部自动释放。理由：
1. **零操作门槛**——玩家只需移动飞机，所有火力自动输出（P1 支柱极致化）
2. **火力渐强**——解锁更多技能 = 同时自动释放更多弹幕 = 视觉更满 = 爽感（P2 支柱）
3. **收费点设计**——提升火力（解锁/升级技能）是核心收费动力，关卡压力来自敌机血量和数量
4. **V2 已有 6 种技能**，当前数量足够，后续版本再扩充技能池
5. 战前选择仍有意义——"这关带哪几个技能最合适？"（当技能池 > 6 时决策更丰富）

**框架集成指导**（v1.8 更新——架构师 PK 修正为单组件方案）：

> **方案：单 SkillComponent + 内部 SkillSlot[6] 数组**（v1.8 确认）
>
> ```
> SkillComponent : IEntityComponent, ITickable
> ├── SkillSlot[6] _slots          // 固定 6 槽，未装备的 slot.IsEmpty = true
> ├── struct SkillSlot:
> │   ├── SkillConfigSO Config     // null = 空槽
> │   ├── float CooldownTimer      // 当前 CD 剩余
> │   ├── float CastTimer          // 前摇/后摇计时
> │   ├── SkillState State         // Idle / Casting / Cooldown
> │   └── bool IsEmpty => Config == null
> ├── Init(Entity, SkillConfigSO[]):
> │   → 按数组填充 _slots[0..N-1]
> ├── Tick(deltaTime):
> │   → for each slot: CD 计时 → Ready → 执行 ISkillEffect → 后摇 → CD
> ```
>
> **为什么不用多实例**（v1.8 架构师 PK 确认）：
> - 现有 Entity 框架 `_components[ComponentType]` 仅支持单实例——改框架影响过大
> - 单组件 + 内部 Slot 数组与 `PassiveComponent(PassiveSlot[3])` 和 `BuffComponent(BuffSlot[])` 模式完全一致
> - 每帧 Tick 一次 SkillComponent，内部循环 6 个 slot——与 Tick 6 个独立组件性能等价但更聚合
>
> **接口约定**：
> - `EntityConfigSO.SkillConfigs : SkillConfigSO[]`（V2 最大长度=6）
> - 出战准备界面写入 `SkillConfigs[0..N]`，N ≤ 6
> - 技能池 > 6 后，出战准备界面变为"从 M 选 6"的选择界面

**SkillConfigSO 结构决策**（v2.1 工具 PK 新增）：

> **方案：Union 结构 + CustomEditor 按 SkillType 显隐字段组**
>
> ```
> SkillConfigSO : ScriptableObject
> ├── SkillType : enum { Scatter, Homing, Laser, Overdrive, Shield, Shockwave }  // V3 预留: EMP
> ├── [通用字段] CooldownTime / CastTime / RecoveryTime / Effects[] / Icon / Description
> ├── [散射] BulletCount / SpreadAngle / BulletPattern
> ├── [追踪] MissileCount / BulletPattern
> ├── [激光] DamagePerTick / TickInterval / LaserDuration / LaserWidth
> ├── [护盾] LinkedBuff
> ├── [火力全开] LinkedBuff
> ├── [冲击波] AreaDamage / BlastRadius
> ```
>
> **为什么选 Union 而非继承/组合**：
> 1. 只有 6 种技能，字段总量 ~15 个——Union 可控
> 2. 独立开发者一人身兼策划和程序，6 种子类 SO 的资产管理复杂度不划算
> 3. Luban 表（如后续迁移）也更简单——一张 `skill_config` 表
> 4. `CustomEditor` 按 `SkillType` enum 显隐对应字段组，解决误配问题
> 5. BuffConfigSO / DotConfigSO 如果后续分化也走 Union 路线（统一模式）

**EntityConfigSO.SkillConfigs 字段归属决策**（v2.1 工具 PK 新增）：

> `SkillConfigs` 字段加在 **EntityConfigSO 基类**上（不拆分 PlayerEntityConfigSO 子类）。
>
> **语义**：`SkillConfigs` 为空数组 = 该 Entity 无技能。运行时 `if (config.SkillConfigs.Length == 0) skip;`。
>
> **理由**：
> 1. Unity SO 新增字段默认 null/default，不会破坏已有序列化（老资产自动为空数组）
> 2. Roadmap P6 精英怪特殊技能模式可复用此字段
> 3. 拆分子类带来的管理成本（两套 SO 类型、两套 Inspector）对独立开发者不划算

#### V2 我方技能清单（6 种）

| ID | 名称 | 触发 | CD | 前摇 | 后摇 | 效果 | 玩家感受 |
|----|------|------|----|------|------|------|---------|
| SK-P01 | 散射弹幕 | Auto | 0.3s | 0 | 0.1s | 5 发扇形（SpreadAngle=30°） | 覆盖面广，清小怪爽 |
| SK-P02 | 追踪导弹 | Auto | 2.0s | 0.3s | 0.5s | 2 发追踪弹（IsHoming=true） | 智能制导，打跑位敌机 |
| SK-P03 | 激光射线 | Auto | 3.0s | 0.5s | 0.3s | 1 发穿透激光（穿透不消失，高伤害） | 一发贯穿一列，仪式感强 |
| SK-P04 | 火力全开 | Auto | 8.0s | 0 | 0 | 自身 Buff：攻速×2 + 子弹数×2，持续 3s | 短暂爆发，屏幕子弹密度暴增 |

> **SK-P04 作用范围**（v1.8 架构师 PK 确认）：
> - ✅ 影响**基础攻击**（AttackComponent）：攻速 ×2 + 子弹数 ×2
> - ❌ **不影响**技能弹幕（SkillComponent 的其他技能 CD/弹幕数量不变）
> - **理由**：若同时影响 6 个技能 → DPS 峰值不可控 → 弹幕数量爆炸。仅加强基础攻击 = 可预测的 4 倍 DPS 提升
> - **弹幕预算验证**：基础攻击 8 发/s × 子弹 Lifetime 3s = 24 在场；火力全开期间 = 16 发/s × 3s = 48 在场，远低于 1024 上限
| SK-P05 | 护盾 | Auto | 10.0s | 0 | 0 | 自身 Buff：免疫 1 次碰撞伤害 | 保命技，容错率提升 |
| SK-P06 | 冲击波 | Auto | 5.0s | 0.2s | 0.3s | AOE：半径 3.0，高伤害，击退所有敌机 | 紧急清场，压力释放 |

**V2 ISkillEffect 实现类清单**（v1.4 PK 新增）：

| ISkillEffect 实现类 | 使用技能 | 职责 |
|--------------------|---------|------|
| `FireBulletsEffect` | SK-P01 散射 / SK-P02 追踪 / SK-P03 激光 | 按 BulletPatternSO 发射弹幕 |
| `ApplyBuffToSelfEffect` | SK-P04 火力全开 / SK-P05 护盾 | 给自身施加指定 BuffConfigSO |
| `DealAreaDamageEffect` | SK-P06 冲击波 | 以施法者为圆心，走 DamageDealer.DealAreaDamage + 击退 |

**技能获取机制（V2）——战前装备制**：

```
技能解锁（长期循环）：
  通关奖励 / 成就达成 / 付费解锁 → 永久解锁新技能 → 加入技能库

战前装备（每局循环）：
  选择关卡 → 进入出战准备界面 → 从已解锁技能中选择最多 6 个装备
    │
    ▼
  确认出战 → 进入战斗 → 所有已装备技能全自动触发，不可中途更换
```

> **收费循环设计**（v1.6 新增）：
> - 关卡压力 = 敌机血量 × 数量 → 玩家 DPS 不够就过不了
> - 提升 DPS = 解锁更多技能 / 升级技能 → **收费点**
> - 免费路径：看广告解锁 / 慢速积累
> - 付费路径：直接购买技能包 / 解锁加速
> - 核心变现公式：**关卡难度递增 → 火力需求递增 → 付费提升火力**

**出战准备界面设计**（v1.7 更新——UI PK 回应）：

> **V2 界面存在价值辩护**：
> - 虽然 V2 全解锁后 6 技能全带入无需选择，但**解锁过程中**每关只有 1~5 个技能，被动只有 1~3 个——**此时确实需要确认当前 build**
> - 更重要的作用是**展示进度和好奇心**：锁定的"???"技能 + 下一个解锁条件 = **推图动力**
> - 但攻方建议有道理：V2 **不需要全屏界面**，改为**半屏 Bottom Sheet** 节省开发和流失
>

> - 从选关界面底部滑出，**不做全屏跳转**
> - 展示：已装备技能横排 + 已装备被动横排 + 关卡预告 + 出击按钮

> - **工时节省**：5h → 3h（省去全屏导航 + 转场动效 + 大量卡片布局）

**交互规格**（v1.2 新增）：

**主动技能选择（多选，最多 6 个）**（v1.7 更新）：
- 点击已解锁技能卡片 → 装备（边框高亮 #4FC3F7 + 右上角 ✓ 标记）
- 再次点击同一个 → 取消装备
- **长按 0.5s** → 弹出轻量 tooltip：技能名称 + CD + 一句话描述（如"5 发扇形覆盖，CD 0.3s"）
- **已选满 6 个时**：点击第 7 个 → 卡片短暂摇晃 + 顶部弱提示"最多装备 6 个技能"（1.5s 后消失）

- V2 只有 6 个技能，全解锁后默认全装备；技能池 > 6 后选择才有意义

**被动技能选择（多选，最多 3 个）**：
- 点击已解锁被动 → 选中（同样边框高亮 + ✓ 标记）
- 再次点击 → 取消选中
- **已选满 3 个时**：点击第 4 个 → 卡片短暂摇晃 + 顶部弱提示"最多装备 3 个被动"（1.5s 后消失）
- 不提供全选/全取消——4 选 3 操作量已极小

- **已解锁**：正常展示图标 + 名称

**技能解锁条件（V2 初始设计）**：

| 技能 | 解锁条件 | 设计意图 |
|------|---------|---------|
| 散射弹幕 | 默认解锁 | 新手友好，上手即有技能体验 |
| 追踪导弹 | 通关第 2 关 | 早期奖励，鼓励推图 |
| 激光射线 | 通关第 4 关 | 中期里程碑 |
| 火力全开 | 通关第 6 关 | 后期奖励 |
| 护盾 | 累计死亡 5 次 | "安慰奖"——越挫越勇的辅助型解锁 |
| 冲击波 | 单关击杀 50 敌机 | 挑战型成就解锁 |

> **设计意图**：
> - 散射弹幕默认解锁 → 玩家第一关就有技能可用，不存在"无技能"的空窗期
> - 解锁条件混合"推图进度"+"成就达成"→ 不同玩家路径都有奖励节点
> - 战前选择创造**有意义的决策**："这关射手机多，用追踪导弹好还是散射好？"
> - 被动技能同样走战前装备 → 每局 build 固定，战术感强

**被动技能获取方式（同步更新）**：

被动技能也走战前装备制，不再通过战斗内道具掉落获取。

```
被动技能解锁 → 加入被动库 → 出战前最多选 3 个 → 全程生效
```

| 被动 | 解锁条件 |
|------|---------|
| 子弹穿透 | 默认解锁 |
| 暴击强化 | 通关第 3 关 |
| 磁吸范围 | 通关第 5 关 |
| 尾翼反击 | 累计被命中 30 次 |

### 3.2 敌方飞机设计（v1.6 重大简化）

**核心改变**：敌机**不需要 AI**，只往下移动。部分敌机可以边移动边射击。

> **设计哲学转变（v1.6）**：
> - ❌ 旧思路：通过 AI 行为多样性制造压力（悬停、蛇形、突进）
> - ✅ 新思路：通过**血量 × 数量**制造压力。玩家必须提升火力才能通关。
> - **收费点**：提升火力 = 解锁/升级技能 = 付费动力

#### 敌机行为规则（极简）

| 敌机类型 | 移动 | 移动速度 | 射击 | HP | 设计意图 |
|---------|------|---------|------|-----|---------|
| 普通机 | 匀速直线下落 | **2.0 单位/s** | 无 | 20 | 数量压力，用量堆 |
| 快速机 | 快速直线下落 | **4.0 单位/s** | 无 | 20 | 时间压力，来得快 |
| 射手机 | 匀速直线下落 | **1.5 单位/s** | 向下单发直射（CD 1.5s） | 40 | 边下落边射击，弹幕+碰撞双重威胁 |
| 散射机 | 匀速直线下落 | **1.2 单位/s** | 3 发扇形向下（CD 2.5s） | 60 | 区域封锁 + 高 HP |
| 精英机 | 匀速直线下落 | **1.0 单位/s** | 追踪弹（CD 3.0s） | 120 | 高 HP 肉盾 + 追踪弹必须躲 |

> **敌机移动速度设计理由**（v2.3 文档工程师 PK 新增）：
> - **普通机(2.0)** = 基准速度，约 6~7 秒穿越屏幕（1334/100≈13.3 世界单位高度）
> - **快速机(4.0)** = 2× 基准，约 3~4 秒穿越——给玩家明显的"快！"感受
> - **射手机(1.5)** < 普通机——下落慢 = 射击窗口更长 = 弹幕威胁更大。设计意图：玩家不着急击杀，但弹幕持续累积压力
> - **散射机(1.2)** / **精英机(1.0)** 更慢——HP 高 + 下落慢 = 在场时间长 = 持续威胁源。逼迫玩家集火优先击杀
> - 所有速度为 **[占位符]**，待 playtest 调整

> **所有敌机统一行为**：出生 → 匀速直线向下 → 到达底线撞基地（或被玩家击杀）。
> **部分敌机额外射击**：射击在移动过程中自动执行，无悬停、无特殊行为。

#### 敌机射击规则

| 参数 | 值 | 说明 |
|------|-----|------|
| 首次开火延迟 | ≥1.0s（从进入屏幕起） | 给玩家反应时间 |
| 射击方向 | 向下（不追踪玩家位置） | 简化逻辑 + 可预判 |
| 射击期间移动 | 不停止，继续下落 | 不做悬停 |

**敌方子弹参数设计原则**：

| 参数 | 值 | 理由 |
|------|-----|------|
| Speed | 4~6 单位/秒 | 比玩家子弹（12）慢得多——玩家必须能看清并反应 |
| Size | 0.2 世界单位 | 比玩家子弹大一点——视觉上更显眼 |
| Lifetime | 3s | 足够穿过屏幕 |
| Damage | 10~15 | 对比基地 MaxHp=100，约 7~10 次命中 Game Over |

> **设计支柱 P4 校验**：敌弹速度刻意做慢——玩家始终能"看到→反应→闪避"，紧张但不绝望。

#### 难度递增方式（v1.6 核心设计）

```
关卡 1：少量普通机（低 HP、少数量）→ 基础火力就能过
关卡 2：更多普通机 + 快速机 → 需要散射/追踪技能
关卡 3：普通 + 射手机（有弹幕）→ 需要走位 + 更强火力
关卡 4：全类型 + 更高 HP → 需要多技能 + 被动配合
关卡 5：大量高 HP + 精英 → 需要满配 build 或付费提升

压力梯度 = HP 倍率 × 数量递增 → 玩家 DPS 需求递增 → 付费解锁火力
```

**敌弹技术约定**（沿用 v1.4）：

> 敌弹是弹幕系统的 Bullet（走 BulletPatternSO + BulletWorld NativeArray），**不是 Entity**。
> - Camp=Enemy → 只命中 Camp=Player 目标（玩家飞机、基地）
> - Entity 系统只管飞机+基地+敌机+道具

### 3.3 碰撞规则更新（V2）

V2 新增"敌方子弹"实体，碰撞表需要更新：

| 碰撞对 | 结果 | 实现 |
|--------|------|------|
| 我方子弹 → 敌机 | 敌机受伤，子弹消失 | 不变 |
| 我方子弹 → 敌方子弹 | **不碰撞**（穿透） | 同阵营子弹不互相碰撞 |
| 敌方子弹 → 玩家飞机 | **基地扣血** + 屏幕震动 + 子弹消失 | 伤害转发 |
| 敌方子弹 → 基地 | 基地扣血 + 子弹消失 | 底线检测 |
| 敌机 → 玩家飞机 | **基地扣血** + 屏幕震动 + **敌机死亡**（v1.6 更新） | 伤害转发 + 敌机销毁 |
| 敌机 → 基地 | 基地扣血 + 敌机消失 | 不变（底线检测） |

**碰撞优先级铁律**（v2.0 架构师 PK 新增）：

> **First-Hit-Wins**：每发弹丸只能命中**一个目标**。碰撞检测命中第一个有效目标后立即标记弹丸消亡，不再继续检测后续目标。
>
> **碰撞优先级**：飞机 > 基地。当飞机与基地碰撞体在同一位置重叠时，飞机优先拦截弹丸（扣 5，而非穿透到基地扣 8）。
>
> **设计理由**：飞机挡弹是 P3 走位策略的核心组成部分——挡弹（扣 5）比漏弹（扣 8）代价更小，是有意义的空间决策。

**关键设计决策**（v1.6 更新）：

> **所有对飞机的伤害都转发给基地**——包括敌弹和敌机碰撞。
>
> 敌机碰撞飞机 → 基地扣血 + 屏幕震动 + **敌机死亡**
>
> **与 v1.5 的区别**：之前敌机撞飞机只是敌机死亡（ContactDmg=9999），不扣基地血。v1.6 改为**也扣基地血**——碰撞不再是"免费消灭敌机"的方式，而是有代价的。
>
> **理由**：
> 1. 飞机不可毁但碰撞有惩罚——玩家不能"站桩靠撞"，必须靠火力消灭敌机
> 2. 因果链更一致：不管被什么打中（弹还是敌机），都扣基地血
> 3. 鼓励提升火力——"我火力不够，敌机撞到我了还扣血"→ 付费动力

| 参数 | 值 | 说明 |
|------|-----|------|
| 敌弹命中飞机基地扣血 | 5~10 | 持续小伤害 |
| 敌机碰撞飞机基地扣血 | 10~15 | 比被弹打到重（v1.6 新增） |

**伤害转发技术方案**（v1.8 更新——架构师 PK 职责拆分）：

> 玩家飞机不可摧毁（无独立 HP 池），对飞机的伤害通过**两条独立路径**处理：
>
> **IDamageModifier 链（对飞机）**（v2.0 架构师 PK 修正——新增 InvincibilityModifier）：
>
> ```
> InvincibilityModifier : IDamageModifier
> ├── Priority = -1（最高优先级，先于所有其他 Modifier）
> ├── ProcessDamage(ref context, target):
> │   → if (InvincibilityComponent.IsInvincible) return false（中断链，伤害归零）
> │   → else return true（继续下一个 Modifier）
>
> DamageRedirectModifier : IDamageModifier
> ├── Priority = 0
> ├── ...（职责不变：转发伤害到基地）
> ```
>
> **职责分离**：InvincibilityModifier 只管"是否免疫"，DamageRedirectModifier 只管"往哪转发"。两者独立。
>
> **路径 A：敌弹命中飞机** → 走 IDamageModifier 链
> ```
> InvincibilityModifier (Priority=-1)
>   → 若无敌中 → return false（中断，弹丸仍消失但不扣血）
>   → 若非无敌 → 继续
> DamageRedirectModifier (Priority=0)
> ├── Target: Entity _baseEntity（基地引用）
> ├── ProcessDamage(ref context, target):
> │   → 构造 adjustedContext（FinalDamage = 固定值 5~10）
> │   → _baseEntity.HealthComponent.TakeDamage(adjustedContext)
> │   → return false（中断链——飞机自身不扣血）
> │   ※ 注意：敌弹命中飞机不触发无敌帧（见下方无敌帧规格）
> ```
>
> **路径 B：敌机碰撞飞机** → 走 EntityCollisionSolver 直接处理
> ```
> EntityCollisionSolver.OnEnemyHitPlayer(enemy, player):
> ├── (1) 检查玩家无敌帧状态 → 若无敌中则跳过
> ├── (2) DamageDealer.DealDamage(baseEntity, fixedDmg=10~15)
> ├── (3) enemy.HealthComponent.Kill()  // 敌机死亡
> ├── (4) 触发屏幕震动 + VFX
> ├── (5) 触发 0.5s 无敌帧
> ```
>
> **职责拆分理由**（v1.8 架构师 PK 确认）：
> - DamageRedirectModifier 仅负责**伤害数值转发**（SRP）
> - "敌机碰撞→敌机死亡"是**碰撞事件的副作用**，由 CollisionSolver 处理更自然
> - 两条路径都触发同一个 InvincibilityComponent 的无敌帧
>
> **注入时机**：玩家飞机 Entity Init 时，由 BattleController 注入基地引用（SO 不引用场景对象铁律）。
>
> **BattleController 初始化时序**（v2.0 架构师 PK 明确）：
>
> ```
> BattleController.InitBattle():
>   (1) Spawn 基地 Entity → baseEntity
>   (2) Spawn 玩家飞机 Entity → playerEntity
>   (3) 注入：playerEntity.DamageRedirectModifier.SetBaseEntity(baseEntity)
>   (4) 注入：playerEntity.InvincibilityModifier.SetInvincibilityComponent(...)
>   (5) 注入：playerEntity.PickupRadius = config.BasePickupRadius
>   (6) 初始化 EntitySpawner（敌机在第一帧后才开始 Spawn）
>   (7) 第一帧 Tick 开始
> ```
>
> **顺序保证**：基地先于飞机 Spawn（1 < 2）；引用注入先于第一帧 Tick（3~5 < 7）；敌机在步骤 6 之后才 Spawn → 第一帧无伤害事件。
>
> **防御性检查**：DamageRedirectModifier.ProcessDamage 开头加 `if (_baseEntity == null) return true`——让伤害穿透到飞机自身（飞机无 HP 组件，伤害自然无效）。

**"飞机挡弹"空间策略**（v1.8 更新——无敌帧规格细化）：

> 敌弹命中飞机 = 基地扣 **5** / 敌弹命中基地 = 基地扣 **8**  
> 敌机碰撞飞机 = 基地扣 **10** + 敌机死亡 / 敌机撞基地 = 基地扣 **15** + 敌机消失
>
> **飞机挡弹仍是合法策略**（扛弹 5 < 漏弹 8），但**飞机挡敌机有代价**（扣 10）。
> - **P4 支柱校验通过**：压力来自"挡还是不挡"的决策
> - **v1.6 设计意图**：玩家不能"站桩靠碰撞消灭敌机"——必须用火力

**无敌帧规格**（v1.8 新增——架构师 PK 确认）：

| 属性 | 值 |
|------|-----|
| 触发条件 | **仅敌机碰撞飞机**触发（路径 B）——敌弹命中飞机**不触发**无敌帧 |
| 持续时间 | 0.5s |
| 免疫范围 | 期间飞机免疫所有伤害来源（敌弹 + 敌机碰撞均不扣血） |
| 视觉反馈 | 飞机半透明闪烁（Alpha 在 0.3~1.0 之间以 10Hz 频率切换） |
| 实现位置 | `InvincibilityComponent : IEntityComponent, ITickable`（独立组件，仅挂载在玩家飞机上） |
| 碰撞行为 | 无敌帧期间碰撞判定**仍存在**但伤害归零——敌弹仍会消失、敌机仍会死亡 |

> **设计理由**（v1.8 架构师 PK 确认）：
> - ❌ 不对敌弹命中触发无敌帧——避免玩家利用低伤害弹触发无敌帧穿越高伤害区
> - ✅ 仅对敌机碰撞触发——敌机碰撞是最重的单次伤害（10~15），0.5s 无敌帧防止连续碰撞秒杀
> - 无敌帧期间碰撞仍消灭敌弹/敌机——不会出现"无敌穿行导致敌弹堆积"的问题
