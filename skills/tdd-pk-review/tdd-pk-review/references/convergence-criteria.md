# PK 收敛判定标准

> 本文件供 PM 在 Phase 3 进行收敛判定时参考。

---

## 快速判定流程图

```
当前轮次的 🔴 高优问题数 = 0?
  ├─ 否 → 继续下一轮（回到 Phase 1）
  └─ 是 → 严重度呈下降趋势?
              ├─ 是 → ✅ 收敛
              └─ 否 → 攻方明确表态可以收敛?
                        ├─ 是 → ✅ 收敛
                        └─ 否 → 达到最大轮次?
                                  ├─ 是 → ⚠️ 强制收敛（记录未解决项）
                                  └─ 否 → 继续下一轮
```

## 详细判定维度

### 1. 严重度趋势分析

统计每轮的严重度分布，观察趋势：

```
Round 1: 3🔴 + 1🟡 + 0🟢  → 高风险
Round 2: 0🔴 + 2🟡 + 1🟢  → 明显收敛
Round 3: 0🔴 + 0🟡 + 1🟢  → 可以收敛
```

**收敛信号**：
- 🔴 数量单调递减
- 总问题数单调递减
- 新问题越来越多是 🟢 低优

**发散信号**：
- 🔴 数量不减反增
- 每轮产生的新问题越来越多
- 回应引发更多问题（说明文档根基有问题）

### 2. 阻塞项判定

| 状态 | 判定 |
|------|------|
| 当前轮次 🔴 = 0 | 无阻塞项，可以考虑收敛 |
| 当前轮次 🔴 > 0 | 有阻塞项，必须继续 |
| 遗留 🟡 > 3 | 虽无阻塞项但风险积累，建议再做一轮 |

### 3. 攻方主观判断

攻方在 Round 2+ 的输出中可能给出收敛意见：
- "无新问题，PK 可以收敛" → 强收敛信号
- "XX 问题回应后即可收敛" → 条件收敛
- 无明确表态 → 由 PM 根据数据判断

### 4. 最大轮次保护

默认最大轮次 = 3。达到最大轮次时：
1. 强制收敛
2. 所有未解决的 🔴 问题降级为"编码期间必须优先处理"
3. 在 PK 总结中明确标注"因达到最大轮次强制收敛"

## 收敛报告模板

收敛后，PM 输出以下格式的总结：

```markdown
## PK 收敛评估

| 维度 | 状态 |
|------|------|
| **PK 轮次** | X 轮完成 |
| **总问题数** | Y 个（Round 1: A + Round 2: B + ...） |
| **全部回应** | Y/Y ✅ |
| **文档版本** | vA.B → ... → vX.Y |
| **阻塞编码的问题** | 0 个 |
| **攻方收敛意见** | "引用攻方的收敛表态" |

**结论：PK 收敛 / 强制收敛（达到最大轮次）。文档 vX.Y 可以进入编码。**

收敛理由：
1. [理由1]
2. [理由2]
3. [理由3]
```

## 边界情况

### 第一轮就没有问题
极少出现但可能发生。如果攻方没有提出任何问题，直接收敛，说明文档质量很高。

### 攻方和守方观点僵持
如果同一个 🔴 问题在两轮中都无法达成一致：
1. PM 做最终裁决
2. 记录分歧点和 PM 的裁决理由
3. 强制收敛该问题

### 发现文档根基性问题
如果 PK 过程中发现文档的核心假设/方向有误：
1. 暂停 PK
2. 向用户报告发现
3. 由用户决定是修正后重新 PK 还是废弃文档
